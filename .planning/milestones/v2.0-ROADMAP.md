## Overview

v2.0 transforms IceFlow SaaS from a single-tenant system into a multi-tenant architecture where each ice factory is a completely isolated tenant. All data is scoped via `factoryId` on every entity. A Super Admin dashboard provides system-wide oversight and subscription management.

## Milestone Summary

### Key Decisions

- **D-01:** System factory with `isSystem=true` owns all pre-existing records
- **D-02:** AsyncLocalStorage + Prisma `$extends` for factoryId auto-injection
- **D-03:** SUPER_ADMIN user has `factoryId=null` for system-wide access
- **D-04:** Direct `factoryId` String field on Customer, Driver, Order, Product (not inherited via relation)
- **D-05:** `@@unique([code, factoryId])` and `@@unique([phone, factoryId])` for factory-scoped uniqueness
- **D-07:** SUPER_ADMIN bypasses factoryId filter via role check before auto-injecting

### Issues Resolved

- Registration endpoint orphaned Factory on partial failure → fixed with `$transaction`
- DriverCount subscription limit not enforced → bulk-assign endpoint now checks limits
- TrialBanner showed for all TRIAL regardless of remaining days → now shows only when ≤3 days
- Entity creation missing factoryId on orders, customers, drivers → Phase 04 fixed all
- GET routes missing explicit factoryId filters → Phase 04 added defensive filters

### Issues Deferred (Tech Debt)

1. **Payment audit log (SADM-04):** `POST /api/payments/confirm` updates subscription but does NOT create Payment records — audit log will be empty
2. **SUPER_ADMIN blocked from `/api/orders`:** Impersonation read blocked by role check
3. **factoryId fallback pattern:** `session.factoryId || session.userId` is semantically wrong

### Technical Debt

- Phase 02 initially had no VERIFICATION.md (created retroactively via `/gsd-verify-work`)
- Payment model has no write path — SADM-04 (audit log) non-functional
- Impersonation read-only enforcement only covers `/api/*` routes
