# Quick Plan: RBAC — Adaptive Sidebar + Route Middleware

## Task Summary

Implement role-based access control: adaptive sidebar menu by role, and middleware route protection. Users are redirected with an error message if they access unauthorized routes.

## Tasks

### Task 1: Update Auth Provider with Role

**Action:** Add `role` field to User interface in auth-provider, update types

**Files:**
- `src/lib/auth-provider.tsx`

**Changes:**
- Add `role?: 'ADMIN' | 'ACCOUNTANT' | 'STAFF'` to User interface
- AuthContext User type includes role
- `/api/auth/me` response already includes role (updated in previous task)

**Verify:**
- `npx tsc --noEmit` passes for auth-provider.tsx

**Done:** User type includes role field

---

### Task 2: Adaptive Sidebar by Role

**Action:** Filter menu items based on user role in sidebar component

**Files:**
- `src/components/dashboard/sidebar.tsx`

**Changes:**
- Define `menuItems` with `roles` property: which roles can see this item
  - STAFF: `/orders`, `/customers` only
  - ACCOUNTANT: `/orders`, `/customers`, `/settle`, `/inventory`
  - ADMIN: all items (`/dashboard`, `/orders`, `/customers`, `/inventory`, `/vehicles`, `/settings`)
- Filter `menuItems` based on `user?.role` before rendering
- Keep collapse behavior for all roles

**Verify:**
- Page renders without TypeScript errors

**Done:** Sidebar adapts to role

---

### Task 3: Route Middleware with Role Protection

**Action:** Add role-based route protection in middleware

**Files:**
- `src/middleware.ts`

**Changes:**
- Define protected routes:
  - `/settings/staff` → ADMIN only
  - `/settle` → ACCOUNTANT, ADMIN
  - `/inventory` → ACCOUNTANT, ADMIN
  - `/vehicles` → ACCOUNTANT, ADMIN
  - `/dashboard` → all authenticated
- If user role is not allowed for the route, redirect to `/dashboard?error=unauthorized`
- Store role in JWT payload or read from session

**Verify:**
- Middleware compiles without errors

**Done:** Middleware protects routes by role
